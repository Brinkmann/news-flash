## C. Risk findings

**C.1 Paid call sites.** Exactly one: `make_flash.py:203`. No `tools=` parameter
anywhere. Server-side web search is absent. *This requirement is met.*

**C.2 Maximum paid calls per run.** One logical call, but up to **3 HTTP
attempts** via SDK default retries. Retries fire on 429/5xx/connection errors.
Billing on aborted attempts is provider-dependent and I have not verified it, so
I cannot state the worst-case cost with confidence. Set `max_retries=0`
explicitly.

**C.3 Cost is unbounded by code.** Nothing measures or caps spend. The only
control is the account-level monthly limit, which is what caused the current
lockout. No per-run hard stop exists as required by §11.

**C.4 Output contamination.** Mitigated by `<FLASH>` markers, but the fallback
branch defeats the mitigation. If the model omits the closing marker, raw output
including process narration is published. This is the exact defect that reached
run 6's MP3.

**C.5 Editorial correctness silently depends on feed availability.** Feed
failures print a line and continue. A story can fail the two-group gate purely
because its second group's feed returned 403. Observed in testing: two BBC feeds
failed on one attempt and succeeded minutes later. There is no record in the
output of which feeds were live, so a thin flash cannot be distinguished from a
thin news day.

**C.6 Stale audio.** The highest-severity finding. `flash.mp3` is overwritten in
place at a fixed URL. If any step fails, the previous day's audio continues to
serve with no indication it is stale. Denise would hear yesterday's news
presented as today's, exactly the failure mode §14 exists to prevent.

**C.7 Digest quorum is a byte count.** `if len(digest) < 500` passes if a single
feed returns content. It does not verify that enough independent source groups
are present for the corroboration gate to be satisfiable.

**C.8 No test suite exists.** Zero fixtures, zero unit tests, zero simulated
runs. Every defect to date was discovered in paid production.

## F. Stop decision

### F.1 Not safe to run

Stop conditions met, per recovery brief §17:

- ☑ The code and specification disagree (B1, B2, B3, B4)
- ☑ Output extraction is not deterministic (B5)
- ☑ Malformed output can be published (B5, B8)
- ☑ Stale audio can be served as current (B7)
- ☑ A required source rule is unresolved (B1 — Bay of Plenty)
- ☑ Deterministic tests have not been performed where possible (D1–D14)

Not met, and worth stating plainly: there is **no paid web search in the
production path**, and **only one editorial call site**. The cost architecture
is sound. The controls around it are not.

### F.2 Correction required to the guardrails specification

The guardrails spec sets `max_tokens` at **1,200 maximum**, reasoning from a
600-word script. The agreed target is 900–1,050 words, roughly 1,200–1,400
tokens. **A 1,200 cap truncates the flash mid-sentence.** Recommend 2,000:
sufficient for the target with headroom, still an effective bound.

The spec also aborts if *any* feed is unreachable. Testing shows feeds fail
intermittently and independently. `BUILD_INSTRUCTIONS.md` §9 already specifies
the correct behaviour: proceed with the rest. The circuit breaker should fire on
a **quorum failure** — fewer than N source groups returning usable content —
not on any single feed.

### F.3 Recommendation on the spend limit

Do not raise it yet. D1–D14 cost nothing and will surface further defects. Raise
it only when the non-paid suite passes and a single manually dispatched run is
the genuine next step.
